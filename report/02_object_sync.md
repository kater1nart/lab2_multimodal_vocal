## 2. Схема мультимодального объекта и правила синхронизации

### Мультимодальный объект

Один объект — один трек каталога (для MTAT — 29-секундный клип трека). Из него формируются три модальности:

```
трек (id)
├── ТЕКСТ: "исполнитель | альбом | название"           -> TF-IDF (символьные 2–5-граммы + слова 1–2) [+ SVD-128 для нейросетевых схем]
├── ВРЕМЕННОЙ РЯД: окно 10 с -> кадры 2048/512 при 22,05 кГц -> 20 рядов:
│     RMS (дБ), спектр. центроид, полоса, спад, плоскостность, ZCR, основной тон (YIN, 60–1000 Гц), MFCC 1–13
│     -> усреднение в 20 шагов по 0,5 с -> матрица 20×20
│     -> для линейных моделей: 120 статистик (среднее, std, min, max, наклон, средний |Δ|);  для BiGRU — сам ряд
└── ИЗОБРАЖЕНИЕ: то же окно 10 с -> лог-мел спектрограмма (128 полос, 0–8 кГц) -> PNG 448×224 -> CLIP ViT-B/32 -> 512-мерный вектор
метка: male | female | group | instrumental
```

### Правила синхронизации

В финансовой постановке синхронизация означает: использовать только то, что известно на момент прогноза. В задаче разметки каталога моментом прогноза является **загрузка трека в каталог**. Отсюда правила:

| № | Правило | Как реализовано |
|---|---|---|
| S1 | На вход подаётся только информация, доступная при загрузке трека: метаданные правообладателя и аудио | Текст = исполнитель + альбом + название. Пользовательские теги MTAT (жанр, инструменты и т.п.) и текстовые описания SDD появляются после прослушивания, поэтому они **исключены из входа** и используются только для построения метки |
| S2 | Все аудио-модальности строятся из одного и того же временного окна | Ряд и спектрограмма считаются из одних и тех же 10 с: MTAT — 0–10 с клипа (как в ЛР1), SDD — 30–40 с 2-минутного фрагмента (пропуск интро). Если трек короче 35 с, берутся первые 10 с |
| S3 | Модальности связаны по идентификатору трека | MTAT: `clip_id` ↔ `mp3_path` ↔ `artist/album/title`; SDD: `track_id` ↔ `track_<id>` в метаданных MTG-Jamendo ↔ аудио из parquet |
| S4 | Одинаковые технические параметры аудио в обоих наборах | Аудио MTAT хранится в 16 кГц, поэтому Jamendo приводится к 16 кГц, а затем оба набора ресемплируются в 22,05 кГц. Без этого правила спектральные признаки Jamendo сдвигаются (см. раздел 8) |
| S5 | Нет утечки между обучением и тестом | Разбиение MTAT по исполнителям (из ЛР1, 70/15/15). Почти-дубликаты по аудио удалены. Энкодеры (TF-IDF, SVD, стандартизация) обучаются только на train. Гиперпараметры подбираются только на val |
| S6 | Временная проверка | В MTAT нет дат релиза, поэтому «отложенный период» проверяется на независимом наборе SDD/Jamendo с датами релиза: 2005–2009 и 2010–2017 (MTAT опубликован в 2009 году, так что вторая группа заведомо позже основного каталога) |

**Аналог часового пояса и биржевого календаря.** Временная привязка в задаче — это смещение окна внутри трека и дата релиза. Окно задаётся правилом S2. Даты релиза Jamendo приведены к году (`RELEASEDATE` → `release_year`), пропусков нет.
